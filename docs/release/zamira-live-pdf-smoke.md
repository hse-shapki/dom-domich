# Z10/Z15: безопасный live smoke четырёх PDF

Этот протокол выполняют только на отдельном демо-доме с синтетическими жителями и уже развёрнутой проверяемой версией. Не создавайте документы прямой записью в live-БД и не подменяйте событие `document.ready`: так нельзя проверить настоящий путь worker → FileStore → MAX.

## Перед нажатием в MAX

Из корня репозитория с настроенным окружением стенда выполните read-only проверки:

```bash
uv run python -m scripts.max_operations probe
docker compose -f deploy/compose.yml ps documents outbox
```

Запишите backend commit, время UTC, демо-сценарий и версии MAX mobile/web. Не копируйте токены, URL загрузки, приватные сообщения и полные журналы в отчёт.

## Четыре документа

| Шаблон | Доверенный источник | Что увидеть в личном чате |
|---|---|---|
| `appeal-v1` | Подтверждённое обращение и доверенная демо-регистрация после согласования черновика | PDF обращения с демо-номером, адресом и hash снимка |
| `resident-position-v1` | Финализация опроса действующей редакции инициативы | Протокол **позиции жителей**, не протокол ОСС; суммарные числа без ID голосовавших |
| `notification-register-v1` | Только разрешённое служебное действие подготовки реестра | PDF с персональными строками только в ЛС уполномоченного адресата |
| `complaint-draft-v1` | Проверенный deadline/followup и доверенный черновик жалобы | PDF помечен черновиком и демо, без утверждения об официальной отправке |

Для каждого вида: выполните обычный сценарий через MAX/разрешённое служебное действие, дождитесь приватного сообщения с файлом, откройте и скачайте **тот же** файл в MAX web и mobile, проверьте читаемость всех страниц, адрес, итоговые числа, маркировку демо, версию шаблона и SHA-256 снимка внутри PDF. В общем чате не должно появиться вложение с документом или личные строки. При наличии доверенного экспорта метаданных сравните SHA-256 скачанных bytes с FileStore hash; сам файл и приватный реестр не прикладывайте к публичному отчёту.

Если для какого-либо вида нет разрешённого live trigger или тестового адресата, запишите его как **не проверено** и причину. Локальная команда ниже подтверждает только кодовый путь; она не является live MAX smoke:

```bash
TEST_DATABASE_URL=postgresql+asyncpg://localhost/dom_domych_test_z_pdf \
  uv run pytest -q tests/infrastructure/test_z10_max_pdf_pipeline.py
```

В [`max-mobile-web-matrix.md`](max-mobile-web-matrix.md) укажите для каждого клиента фактический исход, время UTC, commit и ссылку на закрытое/обезличенное evidence. Пока файла не просмотрели в обоих клиентах, Z15 и G2/G3 остаются открытыми.
