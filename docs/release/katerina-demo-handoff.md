# K16: сценарии Катерины для демонстрации

Дата: 26.09.2026. Это план проверки с альтернативными фразами, а не отметка о
live MAX. Точное состояние реализации — в `context/current-state.md`.
Сценарии используют только синтетических жителей и demo executor; его номер
`DEMO-*` не является номером УК или ГИС ЖКХ. Ускоренный срок в демонстрации
нужно явно подписать как demo clock, не как норматив.

## Четыре пути

| Путь | Фразы, которые может менять жюри | Ожидаемые факты и действия | Локальная проверка |
|---|---|---|---|
| Обычная проблема с поддержкой | «В третьем подъезде на пятом этаже темно у лифта»; «Лампа на площадке 3 подъезда не горит» | Найти кандидата по дому/месту, создать или привязать дело; зафиксировать аудиторию; один житель — один ответ; после порога подготовить обращение с проверенным ответственным | K06/K07/K08/K09 tests; Z poll service tests |
| Малая поддержка | «На площадке течёт, но соседей мало»; «В первом подъезде мокрый потолок, пока никто не откликнулся» | Считать порог от всей зафиксированной категории; по истечении пяти часов demo policy не считать молчание «нет»; адресно запросить evidence у ответивших «да»; пустая категория не имитирует голоса | `test_empty_category_does_not_open_poll_or_fake_support`, Z policy tests |
| Авария | «Пахнет газом на лестнице»; «Щиток дымит, уточню подъезд»; «Прорвало горячую трубу в подвале» | Срочный маршрут без ожидания голосования; при неизвестном месте уточнение; подготовка обращения при проверенном правиле; срок только от доверенной регистрации; review-only followup после deadline | K06/K11/K10/K12/K14 tests |
| Инициатива | «Предлагаю велопарковку во дворе»; «Давайте заменим лавочки у второго подъезда» | Карточка, frozen audience, голоса подтверждённых жителей, отдельные шкалы участия/поддержки; результат — позиция жителей, не официальный протокол ОСС | Z initiative/poll/card/PDF tests |

Для каждого пути оператор меняет хотя бы одну формулировку и место, затем
сверяет `house_id`, case ID/version, источник сообщения, аудиторию, версию
policy и idempotency key. Если нет проверенного правила/ответственного, агент
уточняет; если case закрыт, новое сообщение проверяется как recurrence. Фото
остаётся приватным, пока адресат и публикация явно не разрешены. Отрицательная
проверка результата возвращает дело на следующий шаг и сохраняет ответы.

## Происхождение решений и компонентов

| Объект | Что фиксировать в evidence | Сейчас |
|---|---|---|
| Знания и сроки | `source_id:revision`, reviewed/applicable, house scope, `rule_id`, origin, registration time | K05/K10/K12 сохраняют refs; проверка live норм не выполнена |
| Действия агента | event ID, run ID, case version, tool schema/handler result, запреты | K03/K04/K13 audit и tests; общий MAX inbox composition отсутствует |
| Модель и prompt | GGUF SHA/revision, quantization, llama.cpp build, prompt/schema revision, latency p50/p95 | Кандидат и неуспешный probe описаны в `11-track-k-inference-probe.md`; model/prompt не утверждены |
| Демо-политики | ID/version порога и срока, timestamp snapshot аудитории | Z handoff, `demo-*` policy; это не нормативные нормы |
| PDF | snapshot hash, template/font revision, ссылки на версии дела/опроса | Локальные образцы и QA Z15; доставка через MAX не проверена |
| Сборка | commit, image digest, locked dependencies, MAX client/mobile/web evidence | A17 runbook; G3/tag/digest ещё открыты |

Локальная проверка без тяжёлой модели:

```sh
uv run ruff check src tests scripts
uv run mypy
TEST_DATABASE_URL=postgresql+asyncpg://USER@localhost:5432/TEST_DB uv run pytest -q
```

Критерий живого показа: тот же путь проходит в мобильном и веб-клиенте MAX
с реальными callback/доставкой, PostgreSQL Z repositories, PDF job и
demo executor; доказательства заполняются в
`docs/release/max-mobile-web-matrix.md`. Пока этого нет, перечисленные
локальные тесты подтверждают отдельные части, а не готовый MVP.
