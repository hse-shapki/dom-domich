## Что считаем актуальным

1. Прямые решения команды в обсуждении: все функции Must из backlog; только бот; полный цикл до опроса о выполнении; расширение продукта по фактической готовности.
2. Журнал решений в [open-questions](../open-questions.md), а не устаревшие вопросы в начале файла: один подтверждённый житель — один голос; тестовый реестр; адресная группа; отсутствие ответа не равно «нет».
3. Ограничения трека, приведённые командой; оригинал — [Умный город.pdf](../Умный%20город.pdf).
4. Официальные страницы MAX, проверенные при подготовке спецификации. Технические факты сосредоточены в [03](03-max-integration.md).

В [IDEA](../../IDEA.md) инициативы отложены, а в [backlog](../backlog.md) включены в Must. Здесь инициативы включены согласно прямому решению команды. Формулировки «взвешенное голосование по площади» и план мини-приложения в старом backlog не используются.

## Три разных интерфейса

- **MAX Bot API** — документированный внешний API мессенджера: доставка событий, сообщения, кнопки и файлы.
- **Tools агента** — написанные нами типизированные обработчики бизнес-действий. В исходном варианте вызываются внутри процесса через Tool Registry.
- **HTTP нашего приложения** — webhook и технические health endpoints. Отдельный HTTP transport для tools предусмотрен архитектурно, но не является обязательным этапом.

Собственный API не даёт дополнительных баллов сам по себе. Архитектура сохраняет возможность агенту вызывать ручки, не требует дублировать API MAX и не использует недокументированные сторонние интерфейсы.

## Основные решения

- Python 3.13 + FastAPI/Pydantic; официальный HTTPS API MAX через наш HTTPX-адаптер.
- SQLAlchemy async + asyncpg/Alembic; uv, pytest, ReportLab. Подробности и лицензии — в [стеке](01-scope-and-stack.md).
- Модульный монолит: ingress, worker и scheduler; PostgreSQL как источник состояния.
- Один агент с инструментами; проверяемые доменные операции, восстановление по событиям.
- Открытый self-hosted LLM-контур; выбор размера модели подтверждается evals и измерением на доступном железе.
- Все пользовательские действия доступны в MAX mobile и web.
- Государственные реестры, официальная отправка и статусы исполнителя в MVP явно моделируются.
