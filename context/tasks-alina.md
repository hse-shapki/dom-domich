# Пул Алины — платформа, MAX, реестр и надёжность

[Общий порядок и gates](implementation-plan.md) · [MAX](../docs/engineering/03-max-integration.md) · [архитектура](../docs/engineering/02-architecture.md)

**Владение:** `src/dom_domych/entrypoints/`, `contracts/`, базовые `domain/ports`, `application/residents/`, `application/notifications/`, `application/jobs/`, `infrastructure/max/`, инфраструктура PostgreSQL для core/residents/jobs/notifications, их тесты, `deploy/`, корневые Python-конфиги и интеграция Alembic. Ключи и персональные данные не в Git. Соседние use cases вызываются через согласованные ports. `A` отвечает за сам Bot API MAX; его клиент не выдаём за официальный SDK.

| ID | Задача и результат | Проверка завершения / вход |
|---|---|---|
| **A00** | Создать `uv`/Python 3.13 `src`-проект, `pyproject.toml`, lock, `.python-version`, Ruff/mypy/pytest, `.env.example`, CI. Проверить лицензии зависимостей. | Чистая установка `uv sync --locked`, lint/type/test на базовом пакете и CI. Не считать scaffold продуктом; K00/Z00 параллельно готовят предложения контрактов. |

Назначить владельцев таблиц/событий и общий synthetic fixture. | Pydantic validation и mypy контрактов; fake реализации у K/Z проходят contract tests. Это первая короткая общая граница после A00. |
| **A02** | Поднять PostgreSQL 17/pgvector, SQLAlchemy async engine, Unit of Work, Alembic и миграционный convention; synthetic seed дома: два подъезда, этажи, стояки, несколько жителей в квартире, недоступная личка, неподтверждённый житель. | Миграции на пустой БД и повторный seed без дублей; разные AsyncSession; общая fixture для K/Z. |

| **A04** | FastAPI webhook/health/readiness и доступный MAX тестовый HTTPS endpoint, проверка webhook secret, безопасная нормализация text/callback/attachment/deletion и неизвестных Update. В одной короткой транзакции сохранить raw reference и нормализованное событие в inbox с dedupe key; ответить после commit. | Повтор/подмена webhook не создают второго события; обработчик не ждёт LLM; ASGITransport + PostgreSQL и реальное сообщение в MAX. Финальный Compose/Caddy hardening — A12. |
| **A05** | Реестр домов/квартир/стояков/жителей/проживаний и `HouseContextPort`; явные связи квартир со стояками, house-scoped репозитории и ограничения FK. | Выборка по дому/подъезду/этажу/стояку уникальна; несколько взрослых из одной квартиры учитываются отдельно; чужой дом не виден; PostgreSQL integration tests. |
| **A06** | Онбординг в личке: выбор дома при нескольких связях, demo-подтверждение проживания/возраста/квартиры и доступности диалога; привязка MAX chat к дому, права demo operator. | Неустановленный/несовершеннолетний/неподтверждённый участник не получает право голосовать; общий чат не раскрывает квартиру. Никаких выводов о проживании из MAX user ID. |
| **A07** | Event worker с lease/heartbeat, dispatcher по нормализованному типу, idempotent processing и `Clock`; отдельный процесс от webhook. | Падение после inbox insert и во время обработки восстанавливается по lease; параллельные workers не берут одно событие одновременно. |

| **A10** | Action tokens и callback transport: реальный MAX actor, срок/версия/тип действия, быстрый acknowledgement; маршрутизация в `PollPort` и use cases. | Повтор, пересланная/устаревшая кнопка, чужой actor/дом не меняют голоса; callback подтверждается с корректным transport status. |
| **A11** | MAX attachments: безопасное скачивание evidence, MIME/size/host/redirect проверки; upload URL → файл → token → attachment для PDF; лимитеры диалога/общего RPS/callback, bounded retry `attachment.not.ready`, coalesced edit. | Токен MAX не уходит на upload host; PDF и фото проходят mobile/web smoke; HTTP 200 без success не считается успехом. |

| **A13** | Обработать неполадки MAX и очередей: ограниченный backoff, rate limits, stopped DM/потеря прав, dead-letter, `delivery_unknown` после timeout, redacted structured logs. | Нет бесконечной отправки и ложного `sent`; проверка crash/retry/timeout, корреляция по IDs, токены и тексты жильцов по умолчанию не в логах. |
| **A14** | Интегрировать миграции модулей K/Z и composition root без дублирования use cases; dev polling как отдельный режим без одновременного webhook и с одним consumer. | Одна применимая история Alembic, все стыковые contract tests, реальный G3 runtime; объединённые revisions не переписаны. |

**Условные расширения после G3:** `A18` — transport для голосовых вложений и согласованный ASR-port, только при наличии открытой лицензированной модели и в паре с K18; проверить получение audio в MAX, размер/тип, хранение, исправление распознанного адреса пользователем. Это отдельная задача и не условие MVP.

**Стыки:** для K — `TrustedContext`, event dispatch, `HouseContextPort`, `Clock`, `JobPort`; для Z — `HouseContextPort`, `DeliveryPort`, callbacks, `FileStore` не принадлежит A, документы приходят по готовому file key. Для зависимых задач A использует fake K/Z use cases до gate. Алина проверяет транспортную часть каждого gate и не считает «бот ответил» доказательством правильного доменного результата.
