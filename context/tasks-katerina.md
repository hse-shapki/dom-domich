# Пул Катерины — агент, знания, проблемы и аварии

[Общий порядок и gates](implementation-plan.md) · [tools](../docs/engineering/04-agent-and-tools.md) · [процессы](../docs/engineering/06-runtime-flows.md)

**Владение:** `src/dom_domych/agent/`, модули `application/knowledge/`, `application/cases/`, `application/evidence/`, `application/requests/`, соответствующие `domain/` и `infrastructure/postgres/` модули, `infrastructure/llm/`, `infrastructure/knowledge/`, свои миграции/тесты/evals. Катерина владеет общим `case` aggregate и его состояниями; Замира создаёт initiative как специализацию этого дела. Модель выбирает инструменты, а Case/Request services охраняют права, версии и переходы.

| ID | Задача и результат | Проверка завершения / вход |
|---|---|---|
| **K00** | Для общего A01 вместе с Z00 определить свои команды/результаты `CasePort`, `RequestPort`, `KnowledgePort`, типы событий продолжения и tool schemas; дать fake handlers на synthetic fixture. | После A00/A01 общие contract tests и mypy; код K не импортирует ORM или transport A/Z. |
| **K01** | Составить русский eval dataset: пять классов, смешанные сообщения, неверные/неполные адреса, срочность, дубли/разные места/повтор после закрытия, prompt injection. Зафиксировать допустимые/запрещённые действия и source refs. | Dataset воспроизводим, фразы не ограничены сценарием демо; baseline metrics и критерии критических ошибок записаны до подгонки prompt. |
| **K02** | Проверить на доступном железе llama-server, конкретные open model/embedding revisions, template/tool calling, русский и задержку; `LlmPort`/fake adapter с timeout и ограниченным retry. | Лицензия/хеш/квантование/память/p50-p95 записаны; при отсутствии хоста есть fake путь, но live probe G0 не объявляется пройденным. |
| **K03** | Реализовать async agent runtime: `triage/problem/initiative/followup`, Pydantic JSON Schema allowlist, budget, строгую валидацию args/results, capabilities/house из `TrustedContext`, tool audit и ошибки. | Валидный tool-chain проходит, неверный tool/actor/дом блокируется, нет SQL/shell/произвольного HTTP; fake tools и evals. |
| **K04** | Context builder, run persistence и continuation/pending questions: связать новое событие с актуальной версией дела и ожидаемым ответом, исключить утечку чужого дома и лишних персональных данных в prompt/log. | После рестарта/уточнения запускается новый run с новым state; stale action не коммитится; LLM failure не превращается в успех. |
| **K05** | Knowledge ingestion разрешённых источников и правил: revisions, chunks, reviewed state, применимость, responsible party, deadline origin; FTS + pgvector/embeddings с house/global scope и консервативным fallback. | Ответ содержит source ID/version; неподтверждённый или нерелевантный норматив не становится сроком; данные разных домов не смешиваются. |
| **K06** | Классификация пяти типов и routing: вопрос → источниковый ответ/уточнение, разговор → без дела, проблема/авария/инициатива → соответствующий маршрут; обработка нескольких проблем в одном сообщении. | Evals на новых формулировках; пропуск аварии и выдуманное действие считаются критическими; вопрос без источника не получает выдуманного ответа. |
| **K07** | Candidate retrieval для дедупликации: house/location/object/time, активные и недавно закрытые cases, FTS/vector top-K с фактами; `case.search/get`. | Одинаковая лестница даёт кандидата, разные подъезды/объекты не сливаются по score; fallback без embedding работает. |
| **K08** | `CaseService`: create/attach/recurrence, case messages, evidence refs, versioned events, транзакционный повторный поиск под коротким lock и idempotency. | 12 сообщений одной проблемы дают одно дело; один message привязывается один раз к делу, но может описывать несколько дел; конкурентный create возвращает новый кандидат/конфликт, не создаёт дубликаты молча. |
| **K09** | Обычная проблема: выяснить место, вызвать `AudiencePort`/`PollPort`, открыть подтверждение, дождаться порога или пяти часов; после недостатка поддержки адресно запросить evidence у ответивших «да» и сохранить assessment с sources. | Порог считает Z от snapshot, не агент; N=0/недоставка/повтор автора не имитируют поддержку; персональное evidence не публикуется в общем чате. |
| **K10** | `RequestService`: verified responsible/rule, versioned draft, revision-bound approval/demo policy, `request.prepare/submit/get_status`, связь с документом Z и тестовым ExecutorPort; различать prepared/submitted/registered. | Изменение draft инвалидирует согласование; PDF/чат не приравнены к регистрации; `request.submit` идемпотентен, чужой actor и неполные факты отклонены. |
| **K11** | Аварийный маршрут без ожидания опроса: запрос только критичных уточнений, немедленная подготовка обращения, параллельный сбор evidence, точное место и источник срочности. | Любое подтверждение не является блокирующим порогом; нет нормативного срока без проверенного применимого правила. |
| **K12** | После доверенного `request.registered` запускать SLA jobs от указанной rule origin; на deadline перечитывать request/case и проверять version/status, затем готовить followup или черновик жалобы. | Таймер не начинается от сообщения/PDF; закрытый или устаревший case не эскалируется; demo ускорение обозначено. |
| **K13** | Подключить события `poll.threshold_reached/expired`, `evidence.added`, `request.status_changed/deadline_reached`, `resolution.rejected`, `document.ready` к runtime; не повторять прежний план вслепую. | После нового статуса/evidence агент использует свежую version; negative resolution инициирует новый осмысленный шаг, не удаляет ответы. |
| **K14** | End-to-end тесты дел/обращений/аварий с PostgreSQL, fake A/Z и затем реальными ports; concurrency, чужой дом, stale version, повтор события, проверенный источник, пустая категория. | Полный доменный цикл проходит без MAX; на G3 та же ветка проходит через MAX и DemoExecutor. |
| **K15** | Финальные agent evals/benchmark: точность действий, ложное слияние, пропуск аварий, schema validity, hostile content, p50/p95, число tool calls; зафиксировать model/prompt/hardware revisions. | Критические access/vote/ложная регистрация/ложное закрытие — без провалов; качество и ограничения модели указаны отдельно, без сокрытия средним баллом. |
| **K16** | С K-сценариями помочь release: альтернативные формулировки/локации, четыре живых демо-пути, provenance знаний и prompts/model в комплекте. | Жюри может менять фразу; проблема/малая поддержка/авария/инициатива проходят без заранее зашитого текста. |

**Условные расширения после G3:** `K17` — память дома и ответы по прошлым решениям с revision/source и tenant isolation; `K18` — ASR-текст из A18 как недоверенный черновик, пользователь исправляет адрес до действия; `K19` — повторяемость/ранние признаки проблемы с eval dataset, без автоматической обвинительной отправки по слабому сигналу. Каждое расширение имеет собственный task/commit и не заменяет baseline agent evals.

**Стыки:** `HouseContextPort`/events/jobs/доставка от Алины, `AudiencePort`/`PollPort`/`DocumentPort`/`ExecutorPort`/`ResolutionPort` от Замиры. До интеграции fake implementations и contract tests. Катерина не вызывает MAX напрямую из prompt/tool handler и не создаёт второй подсчёт голосов. Миграции cases/requests/knowledge/agent относятся к этому пулу; общей историей Alembic занимается Алина.
