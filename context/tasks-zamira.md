# Пул Замиры — аудитории, опросы, инициативы, документы и результат

[Общий порядок и gates](implementation-plan.md) · [данные/формулы](../docs/engineering/05-data-and-state.md) · [приёмка](../docs/engineering/08-verification-and-release.md)

**Владение:** модули `application/audiences/`, `application/polls/`, `application/initiatives/`, `application/documents/`, `application/resolution/`, соответствующие `domain/` и `infrastructure/postgres/` модули, `infrastructure/documents/`, `infrastructure/files/`, `infrastructure/executor/`, свои миграции/тесты. Опросы получают actor из callback-события Алины. LLM не голосует и не закрывает дело собственным выводом. Общий case aggregate принадлежит Катерине; Замира ведёт initiative specialization и результат через порты.

| ID | Задача и результат | Проверка завершения / вход |
|---|---|---|
| **Z00** | Для общего A01 вместе с K00 согласовать `AudiencePort`, `PollPort`, `InitiativePort`, `DocumentPort`, `ResolutionPort`, `ExecutorPort`, snapshots/events и границы callback; фейки `HouseContextPort`/`CasePort`/`DeliveryPort`. | После A00/A01 contract tests и mypy на общих fixtures; свои доменные tests не ждут живого MAX. |
| **Z01** | Зафиксировать versioned demo policies: подтверждение проблемы, позиция по инициативе, проверка выполнения; denominator/ceil, N=0, deadline boundary, изменение аудитории, приоритет отрицательного результата. Отделить пример 20% и предложенные пороги от закона. | Таблица правил и параметризованные unit tests; неутверждённые числа помечены demo defaults и открытым решением. |
| **Z02** | Подготовить синтетические сценарии: дом/подъезд/этаж/стояк, 12 жалоб, повтор одного жителя, недоставленная личка, поздний голос, изменённая инициатива, отрицательное выполнение; fake repositories. | Fixtures демонстрируют корректные eligible/reachable counts и все ветки, включая N=0; seed согласован с A02. |
| **Z03** | AudienceService: snapshot критерия и состава подтверждённых взрослых жителей по дому/подъезду/этажу/явному стояку; уникальность жителей, snapshot revision и изменение категории с историей. | Несколько квартир/проживаний не дают дубликат жителя, delivery state не меняет знаменатель; tenant isolation и riser не угадывается из номера квартиры. |
| **Z04** | PollService: открыть три вида опросов, eligibility, policy snapshot, уникальный answer/upsert только во время окна, threshold event единожды, финализация на deadline. | 12 нажатий одного жителя = один голос, одновременное пересечение порога = одно событие, молчание не «нет», ответ на границе срока по правилу [05](../docs/engineering/05-data-and-state.md). PostgreSQL concurrency tests. |
| **Z05** | Callback-facing command handler: action token/actor из A10 → проверка snapshot/дома/версии/открытости; результаты для acknowledgement и карточки. | Подмена actor, чужой дом, недопустимый участник и stale action отвергнуты без записи; LLM не имеет `poll.answer`. |
| **Z06** | InitiativeService: case kind=initiative через K `CasePort`, автор, формулировка/ревизии, аудитория и опрос позиции; изменение текста запускает новую ревизию и требует новых голосов. | Произвольная формулировка проходит; прежние голоса не переходят молча; права автора и дома проверены. |
| **Z07** | Карточки инициативы/проблемы/статуса: участие `answered/eligible`, поддержка `yes/eligible` и `yes/answered`, progress/версия/demo label; DTO для edit через A `DeliveryPort`. | Шкала участия не подменяется поддержкой, N=0 понятен, персональные ответы не выводятся в общий чат, быстрые изменения coalesced на A. |
| **Z08** | Напоминания не ответившим подходящим жителям с частотным лимитом; финальное решение позиции по demo policy: supported/not_supported; связь поддержанной инициативы с общим исполнением. | Недоставка не меняет eligible, «не ответил» не равно «против»; неподдержанное предложение не отправляется как принятое. |
| **Z09** | FileStore: постоянное хранение evidence/PDF по внутреннему ключу, MIME/size/hash/ACL, retention/delete policy; документы используют immutable serialized snapshot с case/poll/audience/rule revisions. | Хеш и snapshot воспроизводимы; нет обхода пути именем файла, чужой дом не читает файл; PDF не перечитывает меняющиеся голоса. |
| **Z10** | ReportLab/Platypus в ограниченном process pool: PDF обращения, протокола **позиции жителей** (не ОСС), реестра уведомлений и черновика жалобы; шрифт с кириллицей/лицензией, template version, demo label, file hash, событие `document.ready`. | Все четыре файла визуально проверены на длинных адресах/таблицах и страницах; числа совпадают с snapshot, приватные ответы не раскрыты, MAX download mobile/web на G2/G3. |
| **Z11** | DemoExecutor за `ExecutorPort`: idempotent submit/register/status, тестовый номер и `source=demo_executor`, служебное действие только для авторизованного demo operator. | Житель не ставит `done`, duplicate submit не создаёт вторую регистрацию, card/PDF честно маркируют демо. |
| **Z12** | ResolutionService: по доверенному `done` создать опрос **исходной** аудитории/категории и outbox/jobs; отделить `external_status` от `workflow_status`. | `done` без resident check оставляет дело открытым; новая аудитория не подменяет исходный знаменатель; недоставка не сокращает группу. |
| **Z13** | Подсчитать outcome по frozen policy: confirmed → `closed`, negative threshold → `reopened` и `resolution.rejected`, недостаточно ответов → `resolution_unconfirmed`; закрытие отменяет/нейтрализует будущие jobs. | «Нет» имеет заданный приоритет, молчание не считается успехом, повторный callback/позднее событие не меняет итог; case K меняется через согласованный use case. |
| **Z14** | Интеграционные тесты на PostgreSQL и MAX transport для инициативы/опроса/PDF/исполнения/возврата; восстановление после crash PDF/Executor/status worker, ревизии. | На G3 цикл обычной проблемы и инициативы завершается подтверждением или возвратом; источник, версии и delivery state видны в истории. |
| **Z15** | Проверить все PDF как артефакты: кириллица embedded, многостраничность, соответствие полей/snapshot/hash, объём персональных данных, статус demo; зафиксировать screenshots/результаты mobile/web. | Генерация без ошибок недостаточна: файлы открыты и просмотрены в обоих клиентах, указаны шаблон/шрифт/commit. |
| **Z16** | Передать release материалы: политика/числа, синтетические данные, образцы четырёх PDF, схема ручного demo executor и проверки результата, licenses font/ReportLab, real-vs-demo inventory. | По инструкции можно воспроизвести позитивный и отрицательный outcome без ручного изменения БД; пакет соответствует [08](../docs/engineering/08-verification-and-release.md). |

**Условные расширения после G3:** `Z17` — анализ фото через отдельный открытый vision adapter с оценкой неопределённости, без заявления об увиденном при текстовом baseline; `Z18` — сводки, повторяемость и адресные напоминания на истории/JobPort с ограничением частоты. Их включение требует отдельной лицензии/evals и согласования с K17/K19; в MVP достаточно принять фото как evidence без автоматического зрения.

**Стыки:** от Алины — выборка подтверждённых жителей, callback identity, доставка/jobs; от Катерины — `CasePort`, `RequestPort`, case facts и source refs. Замира владеет policy и голосами, но не создаёт отдельную модель проживаний или дел. До получения реальных ports использует фейки, а на gate доказывает связанный сценарий.
